# 动作详解

本文件是每个动作的**完整参数、默认值、返回字段和动作解释**。

约定：

- `<cua>` 代表 client 的完整路径（通常是 `<本 skill 目录>\bin\simple_cua.exe`）
- **所有坐标都是显示器内的局部坐标**（详见 SKILL.md 的「坐标约定」）
- `--monitor` 默认都是**光标当前所在的那台显示器**

---

## `ping`

检测 server 是否在跑。

**参数**：无

**返回**
```json
{"ok":true,"op":"ping","version":"0.1.0","pid":12345,"integrity":"S-1-16-8192 (Medium)","elevated":false,"uptime_s":42}
```

| 字段 | 含义 |
|---|---|
| `integrity` | server 进程的完整性级别 |
| `elevated` | 是否以管理员（完整令牌）运行 |

**动作解释**

> ⚠️ **`integrity` 必须是 `Medium`。**
>
> 如果显示 `Low`，说明 `cua_server.exe` 待在一个带 Low 完整性标签的目录里（比如被放进了某个 DSH 工作区）。这时它**一切输入注入都会静默失效** —— 不报错，就是没反应。
>
> 遇到这种情况：**不要做任何动作**，先让用户把 server 换到别处再启动。

## `get_state`

看当前状态。没有副作用，可以随时调。

**参数**

| 参数 | 说明 |
|---|---|
| `--cursor` | 只返回光标相关 |
| `--held` | 只返回当前按住的键和鼠标按钮 |
| 两个都给 | 返回这两项（不返回显示器等） |
| 都不给 | 返回全部 |

**返回**
```json
{"ok":true,"op":"get_state",
 "cursor":{"local":[900,500],"monitor":0},
 "cursor_flags":"SHOWING",
 "monitor_count":1,
 "monitors":[{"i":0,"dev":"\\\\.\\DISPLAY1","size":[1920,1080],"work":[0,0,1920,1020],"primary":true,"dpi":120,"scale":125}],
 "foreground":{"class":"Notepad","title":"无标题 - 记事本"},
 "under_cursor":{"class":"Edit","title":null},
 "clip_screen":[0,0,1920,1080],
 "held":""}
```

| 字段 | 含义 |
|---|---|
| `cursor.local` / `cursor.monitor` | 光标在**哪台显示器**的**局部坐标** |
| `cursor_flags` | `SHOWING` / `SUPPRESSED` / `none` |
| `monitors[].size` | 该显示器的**物理像素**尺寸 —— 坐标合法范围就是 `0..size-1` |
| `monitors[].work` | 工作区（扣掉任务栏），同样是局部坐标 |
| `foreground` | **前台窗口** —— 打字就是发给它 |
| `under_cursor` | 光标底下的窗口 |
| `clip_screen` | ⚠️ 唯一的**屏幕坐标**字段（可能横跨多屏），只用来排查"光标被某个程序限制住了" |
| `held` | 当前按住的键和鼠标按钮 |

**动作解释**

- `held` 查的是**系统层面**的状态，所以它**会包含用户真人正按着的键**。看到按键不一定有问题，不必定代表 server 按住了什么。

## `screenshot`

截当前显示器的图。

**参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--monitor N` | 光标所在显示器 | |
| `--out 文件名` | `scua-screenshot.png` | **必须以 `.png` 结尾**；相对路径相对 **client 被调用时的 cwd** |

**返回**
```json
{"ok":true,"op":"screenshot","monitor":0,"size":[1920,1080],"bytes":220460,"path":"D:\\work\\scua-screenshot.png"}
```

**动作解释**

- 返回的 `path` 是**图片的绝对路径**，用它去读图。
- **图上的坐标 (x,y) 就等于该显示器内的局部坐标 (x,y)** —— 不需要任何换算。
- ⚠️ **默认文件名是固定的，会覆盖**。所以连拍两台显示器时，第二张会把第一张盖掉 —— 需要保留就显式给 `--out`。
- ⚠️ **截图里看不到鼠标指针**。光标是显示系统单独合成的一层，`BitBlt` 抓不到它。

## `zoom`

放大某个小区域再截图，用来看清细节（比如一个小图标、一行小字）。

**参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `X Y W H` | 必须 | 该显示器内的局部坐标 |
| `--scale N` | 2 | 放大倍数，范围 1–16 |
| `--monitor N` | 光标所在显示器 | |
| `--out 文件名` | `scua-zoom.png` | 规则同 `screenshot` |

**返回**
```json
{"ok":true,"op":"zoom","monitor":0,"region":[800,400,320,240],"scale":2,"size":[640,480],"bytes":18422,"path":"D:\\work\\scua-zoom.png"}
```

**动作解释**

- 放大是**最近邻**（像素是硬的，不做插值）—— 所以放大后不会出现模糊的过渡色，适合核对细节。
- 区域必须**完整落在同一台显示器内**，否则会被拒绝（`region-not-on-monitor`）。
- 区域开太大时，图片本身也会很大；读图的工具可能进一步缩放它，那样就失去放大意义了 —— 所以 `W H` 尽量控制在几百像素以内。

## `move`

移动鼠标。

**参数**

| 参数 | 说明 |
|---|---|
| `X Y` | 该显示器内的绝对坐标 |
| `--dx N --dy N` | 相对当前光标位置的偏移 |
| `--monitor N` | 默认光标所在显示器 |

> `X Y` 和 `--dx/--dy` **只能给一个**。

**返回**
```json
{"ok":true,"op":"move","monitor":0,"at":[900,500],"err_px":0}
```

**动作解释**

- 移动之后会**读回验证**；只有落点与目标完全一致才算成功。落点不符会返回 `landed-elsewhere`（多半是被屏幕边缘钳住了）。
- `--dx/--dy` 是**屏幕坐标下的偏移**，所以它可以跨越显示器。
- 目标不在任何显示器上时**直接拒绝**，不会让它被静默钳到边缘。

---

## `click`

点击，或者"移动过去再点击"。

**参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `X Y` | 可选 | 给就先移动过去（并验证）；不给就在光标当前位置点 |
| `--monitor N` | 光标所在显示器 | |
| `--button` | `left` | `left` / `right` / `middle` / `double`（`double` = 左键双击） |

**返回**
```json
{"ok":true,"op":"click","monitor":0,"at":[900,500],"button":"left","moved_px":0,
 "foreground":{"class":"Notepad","title":"无标题 - 记事本"}}
```

返回里的 `foreground` 是**点击之后**的前台窗口 —— 可以用来确认点中了想要的东西。

**动作解释**

- **点击前会亮 1 秒蓝色圆圈，这个时间固定、不可调。** 这是留给人的反应时间。
- 如果这 1 秒里光标被移动**超过 50px**，会返回：

  ```json
  {"ok":false,"op":"click","code":"cancelled-by-user-motion","msg":"..."}
  ```
  退出码 **5**。**这是正常结果（人否决了），不是故障，不要盲目重试。**
- 如果人只是**小幅挪动（不到 50px）**，点击会**落在挪动之后的位置** —— 这是有意的：agent 瞄偏一点时，人可以在这一秒里把它推到正确的地方。

## `drag`

从一点拖到另一点。

**参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `X1 Y1 X2 Y2` | 必须 | 该显示器内的局部坐标，**起点终点要在同一台显示器内** |
| `--monitor N` | 光标所在显示器 | |
| `--button` | `left` | `left` / `right` / `middle`（没有 `double`） |
| `--steps N` | 按距离自动（约每 20px 一步） | 中间插入的移动步数，范围 2–500 |
| `--hold MS` | 120 | 按下之后到开始移动之间的等待，范围 0–5000 |

**返回**
```json
{"ok":true,"op":"drag","monitor":0,"from":[400,300],"to":[900,600],
 "steps":25,"button":"left","moved_px":0,"ms":430}
```

**动作解释**

- 同样有 **1 秒预备圆圈**，取消规则和 `click` 一样。
- **起点以最终光标位置为准**（人可以在预备窗口里帮推），**终点用参数给的坐标**。
- **分步移动是必要的，不是多余**：按下之后从起点一步跳到终点再抬起，很多程序（浏览器拖放、自定义控件）会把它当成"点击"而直接忽略。
- 无论中途出什么问题，**抬起一定会发出** —— 不会留下"鼠标一直按着"的状态。

## `scroll`

滚轮。滚的位置就是**光标当前位置** —— 要换位置请先 `move`。

**参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--dy N` | 0 | **正数 = 向下滚动**，单位是"格" |
| `--dx N` | 0 | 正数 = 向右 |
| | | 两个都不能超过 ±100；都为 0 会报错 |

**返回**
```json
{"ok":true,"op":"scroll","monitor":0,"at":[900,500],"dy":3,"dx":0,"notches":3}
```

**动作解释**

- 滚轮消息发给**光标底下的窗口**，所以"在哪滚"很要紧。
- 一格一个事件（不是一次发一个很大的值）—— 很多程序对"一次滚轮事件"和"一口气滚很多格"的反应并不一样（分页、动画）。

## `type`

输入一段文本（逐字符发送）。

**参数**

| 参数 | 说明 |
|---|---|
| `--text "..."` | 直接给文本。适合简单文字 |
| `--b64 <base64>` | 文本 UTF-8 字节的 base64，纯 ASCII。与 `--text` 只能给一个 |
| `--interval MS` | 每字符之间的间隔，默认 0，范围 0–1000 |

**返回**
```json
{"ok":true,"op":"type","source":"b64","chars":11,"interval_ms":0,
 "foreground":{"class":"Notepad","title":"无标题 - 记事本"}}
```

**动作解释**

- **打字发给「焦点窗口」，和光标位置无关。** 所以要先 `click` 到目标窗口，或者自己确认焦点是对的。返回里的 `foreground` 就是文字实际打进去的那个窗口，可以用它核对。（不过最终仍以截图为准）
- **文本里的换行等于「按回车」。**
  如果换行走的是字符通道，那么 Chromium 系应用（VS Code、Chrome）会把 VK_PACKET 事件中的控制字符整个过滤掉。
  所以换行在本程序中，是发一个真正的回车键。
  代价是：**在单行输入框 / 地址栏里，换行会触发提交。**
- **要"纯文本换行、不触发提交"，可以考虑走剪贴板**：
  ```
  <cua> clipboard set --b64 <内容带换行的 base64>
  <cua> key ctrl+v
  ```
- 一段文本最多 **1024 字节（UTF-8）**，超过会报 `too-long`。更长的内容请走剪贴板。
- **优先用 `--b64`**：它绕过命令行的引号规则，含引号、换行、中文的文本都不会被 shell 弄坏。

## `key`

按一个键，或一组组合键。

**参数**

| 参数 | 说明 |
|---|---|
| `CHORD` | 例如 `enter`、`ctrl+c`。与 `--show` 互斥 |
| `--hold MS` | 按住时长，默认 30，范围 0–3000 |
| `--show` | 列出所有合法键名、组合格式、示例，以及黑名单 |

**返回**
```json
{"ok":true,"op":"key","chord":"ctrl+v","keys":["ctrl","v"],"hold_ms":30,
 "foreground":{"class":"Notepad","title":"无标题 - 记事本"}}
```

**动作解释**

- 组合键**最多 4 个键**，用 `+` 连接；最后一段是主键，前面的都作为提前按住的修饰键。
- **黑名单不可绕过**，被拦时退出码 **5**：
  `alt+f4`、`win+l`、`win+ctrl+shift+b`、`shift+delete`、`scrolllock`、`pause`、`apps`，以及 **`F1`–`F24` 整类**。
  判定用的是**「包含」而不是相等** —— 所以 `alt+f4+a`、`win+alt+l` 这种"多带一个键"的写法**同样会被拦住**。
  （`F1`–`F24` 被拉黑是因为笔记本上这些键通常是双功能的：媒体、亮度、飞行模式、触控板开关……发出去到底是哪个，取决于 Fn 锁的状态。）
- 打一个字符请用 `type`，不要用 `key`。

## `clipboard`

读 / 写 / 清空剪贴板。**只支持文本。**

**参数（子命令）**

| 子命令 | 说明 |
|---|---|
| `get [--out 文件名]` | 读剪贴板文本 |
| `set --text "..."` / `set --b64 <base64>` | 写剪贴板 |
| `clear` | 清空剪贴板 |

`--out` 只在 `get` 下有效，**必须以 `.txt` 结尾**，规则同 `screenshot`。

**返回**
```json
{"ok":true,"op":"clipboard","action":"get","chars":11,"bytes":18,"truncated":false,"text":"line1\nline2"}
```
```json
{"ok":true,"op":"clipboard","action":"set","chars":11}
```

**动作解释**

- `get` 内联返回的内容**最多 1KB**（按 UTF-8 字符边界截断，`truncated` 会置 `true`）。要全文就用 `--out` 落文件。
- 剪贴板里**不是文本**时（图片、文件列表），`get` 会报 `no-text`，退出码 4。
- `clear` 之后再 `get` **同样会报 `no-text`** —— 空剪贴板和"没有文本"在这里是一回事。
- 剪贴板是**共享资源**，别的程序可能正占着它；server 会自动重试几次，但仍然可能失败（`set-failed` / `clear-failed`）。

## `release_all`

松开所有被按住的键和鼠标按钮。

**参数**：无

**返回**
```json
{"ok":true,"op":"release_all","released_buttons":"","released_keys":""}
```

**动作解释**

> ⚠️ **它会打断用户当前的操作。**
>
> 它用的是**系统层面**的检查（因为只有在出错的时候才需要它，而那时只有系统状态可信）。这意味着它**分不出"我注入的"和"用户真人按着的"** ——
> - 用户正按着 `Ctrl` / `Shift`，会被一起松开
> - 更严重的是：**用户正在拖拽时（左键按着），拖拽会在中途结束**，窗口或文件可能被丢在非预期的地方
>
> 所以**只在异常恢复时用**。正常情况下每个动作结束都会自己释放。

## 附：返回值的通用形状

成功：

```json
{"ok":true,"op":"<动作名>", ...动作自己的字段...}
```

失败：

```json
{"ok":false,"op":"<动作名>","code":"<机器可读的原因>","msg":"<给人看的一句话>"}
```

**判断成功与否，看 client 的退出码**（见 `errors.md`）—— 它是 0 就是成功。
